# skill-curator

当前 `skill-curator` 版本为 **1.01**。它可以理解成一个“GitHub 项目审核、选型、适配与安装管家”。目前在发送github链接后会自动触发

## 核心作用

它解决的不是单纯“怎么安装”，而是安装前后的完整决策：

1. 判断项目是什么  
   识别它更适合做 Codex Skill、MCP、CLI、脚本、工作流、Prompt，还是其他工具。

2. 判断是否值得使用  
   结合当前需求、当前 Codex 项目和其他本地项目，判断它是否真正有价值。

3. 检查功能重复  
   对比已经安装的全局 Skill，发现替代、互补或冲突关系。

4. 比较同类项目  
   实时搜索 GitHub 上3–5个代表性项目，从匹配度、完整度、Codex 适配性、活跃度、Star 和安装复杂度进行比较。

5. 输出固定审核  
   安装前必须依次说明：

   - 是什么
   - 功能说明
   - 安装完成后如何使用
   - 适合什么形态
   - 对你的价值
   - 重复项（存在时）
   - 同类项目
   - 最终建议
   - 授权后的安装动作

6. 获得授权后安装  
   只有你明确要求安装或接入时才会执行，优先安装到 Codex 全局 Skill 目录。

7. 适配第三方 Skill  
   可以修正路径、frontmatter、Codex 调用说明等小范围兼容问题，并给个人 Skill 补充中文 `short_description`。

8. 验证与回滚  
   安装后进行基础验证；失败时撤销本次修改，不影响原有文件。

9. 记录到 Obsidian  
   安装成功后，尽可能调用现有 Obsidian 相关 Skill，按照指定模板撰写完整说明文档。

## 如何使用

### 自动触发

直接发送 GitHub 仓库主页链接：

```
如：https://github.com/owner/repository
```

此时默认只审核，不安装。

### 审核并安装

```
https://github.com/owner/repository

审核后，如果适合就帮我安装。
```

它会先完整审核，再执行已经授权的安装。

### 手动调用

没有 GitHub 仓库主页链接时，使用 $skill-curator：

```
$skill-curator 帮我判断这个工具更适合做 Skill、MCP 还是脚本
```

```
$skill-curator 检查这个本地 Skill 是否与现有 Skill 重复
```

### 深度评审

```
$skill-curator 深度评审这个项目，包括维护状态、代码质量、供应链风险和迁移成本
```

只有明确要求时才会进入深度评审。

## 适合的使用场景

- 看到一个 GitHub 项目，不确定值不值得安装。
- 不确定某个项目应该做成 Skill、MCP、CLI 还是脚本。
- 安装前想检查是否与现有 Skill 重复。
- 希望比较几个同类 GitHub 项目。
- 想把 Claude Skill 或其他 Agent Skill 适配为 Codex Skill。
- 想安装非 Skill 工具，但不确定 Codex 的接入方式。
- 希望安装完成后获得真正的使用教程，而不是重复安装步骤。
- 希望自动生成 Obsidian 安装和使用记录。

## 不适合的场景

它不会因为普通软件推荐、一般代码审查或随口提到 GitHub 而自动触发，也不会：

- 未经授权直接安装；
- 自动更新已有工具；
- 自动卸载旧 Skill；
- 为了接入工具而进行未经确认的大规模改造；
- 把安装命令当作安装后的使用说明。
